# Nomon 改进设计方案 —— 对标 Oura App 的「先给予、后索取」结构

> 版本：v1.0 ｜ 日期：2026-08-18
> 作者：Harvey（提出问题与方向）+ Claude Code (Opus 5)（方案撰写）
> 对象：Nomon 测试版（肌肉损伤 / 运动恢复 AI 助手）

---

## 一、问题诊断：为什么现在「不知道该输入什么，也不知道有什么用」

从测试版四个页面（Today / Myself / Insights / Calendar）的实际体验看，有四个结构性问题。它们不是文案问题，是顺序问题。

### 1. 给予与索取的顺序反了
- **Oura**：戴上指环睡一觉，第二天早上就有三个分数（Readiness / Sleep / Activity）和一整套解释。用户是被「我想搞懂这个数字」驱动，才去读知识、打标签。**先给价值，再要投入。**
- **Nomon 现在**：进门就是一个空文本框「写下来」，Insights 页明说 "A pattern shows after a few entries"。用户的付出在前，回报在一个未知的将来。

这是新用户流失的第一杀手。用户不是不愿意输入，是不愿意为一个还没证明自己有用的东西输入。

### 2. 把最难的输入方式设成了默认
「肩膀举高时有点痛」这种自由文本，对用户是一道开放式作文题：不知道该写多细、不知道写了会怎么用、怕写错。

Oura 的主输入是零成本的（传感器），辅助输入是轻量点选（Tags）。Nomon 没有传感器——但**完全可以用「结构化自评」替代作文**：点身体部位 → 选诱因场景 → 做 2–3 个标准动作 → 拖滑条打分。信息量远大于一句话，认知成本却低得多。

### 3. 完全缺失「知识」这一层
Oura 里「睡眠分数、生物钟、睡眠负债、睡眠规律性」这些知识卡，承担的不只是科普功能，更是**在用户还没有任何数据时，告诉用户「这个 app 懂什么、能帮你什么」**。它是不依赖用户数据就能消费的内容资产。

Nomon 目前完全没有这一层，所以首屏只能是空的，用户也就无从判断值不值得投入。

### 4. Myself 页展示的是系统内部状态，不是用户关心的东西
"Thoughts 2 / 1 signal taking shape" 是开发者视角。用户真正关心的是三件事：
**我的肩膀现在怎么样？什么时候能好？今天能不能去练？**

## 二、核心思路：把 Oura 的四层结构原样搬过来

| Oura 的层 | 作用 | Nomon 的对应物 |
|---|---|---|
| 指环传感器（被动采集） | 零成本获得数据 | **动作自查（Movement Check）**：2 分钟、3 个标准动作、点选+滑条 |
| Readiness / Sleep / Activity 分数 | 一个可解释的数字，天天有理由回来 | **恢复分数 Recovery Score**（按受伤部位，0–100） |
| Contributors（HRV / 静息心率 / 体温…可点开） | 让分数可解释、可信任 | **贡献因子**：疼痛强度 / 活动度 ROM / 日常功能影响 / 变化趋势 |
| Learn 知识库 | 冷启动内容 + 教育 + 解释弹药 | **Nomon 知识卡库**（12–20 张，见第六节） |
| Tags 标签 | 建立因果假设 | **诱因标签**：久坐 / 深蹲日 / 跑量突增 / 睡姿 / 提重物 |
| Trends 趋势 | 长期价值 | **恢复曲线 + 恢复阶段**（急性期 / 恢复期 / 重返运动） |

一句话概括改法：**把「先让用户描述」改成「先让用户认识自己的身体状态」。**

---

## 三、四个 Tab 的重新设计

### Tab 1 · Today —— 从空白页改成「身体地图 + 今日卡 + 知识流」

现状：大标题 + 一大片空白 + 底部一个文本框。
改成自上而下三段，**任何时候都不为空**：

**① 顶部：身体地图（Body Map）**
一个人形剪影（正面 / 背面可切换），可点选部位。
- 有记录的部位显示状态色（红=急性 / 黄=恢复中 / 绿=已缓解）
- 没有任何数据时，也是完整可交互的：**「哪里不舒服？点一下。」**

这是替代空文本框的关键。点一个部位的成本几乎为零，而它给出的信息比用户随手写的一句话更结构化。

**② 中部：今日卡片**
- 有数据时：`肩部 62 分（比昨天 +5）` + 一句自然语言解释（"夜间痛消失是这次主要的改善项"）+ 今日三条建议（做什么 / 避免什么 / 观察什么）
- 无数据时：一张显眼的行动卡 **「2 分钟自查，看看这是什么问题」**

**③ 下部：知识卡流**
永远有内容的信息流。新用户第一次打开，看到的就是这些卡填满屏幕，滑两下就明白「这个 app 懂运动损伤」。

---

### Tab 2 · 「2 分钟自查」—— 替代自由文本的核心流程

五步，一步一屏，**全部是点选和滑条**，不需要打字：

1. **部位** — 身体地图点选（肩 / 膝 / 腰 / 踝…，再细分前后侧）
2. **什么时候开始的** — 今天 / 这周 / 一个月内 / 更久（决定「急性 vs 慢性」分支，这是后续所有建议的分岔点）
3. **怎么弄的** — 举重物 / 跑步 / 球类扭伤 / 睡醒就痛 / 说不清（说不清是合法选项）
4. **动作测试** — 给 2–3 个针对该部位的标准动作，每个配示意图或 3 秒短视频：
   - 「手臂从体侧举过头顶」→ 滑条打疼痛 0–10 + 三档选「能举到哪」（过头 / 到肩 / 举不起来）
   - 这是 Nomon 版的「传感器读数」，可量化、可复测、可画曲线
5. **红旗筛查** — 麻木 / 明显无力 / 关节外观变形 / 夜间剧痛痛醒 / 发烧。**命中任意一条 → 流程立即转向「建议尽快就医」，不给恢复建议。**

最后才是自由文本：**「还有什么想补充的？（可跳过）」** —— AI 对话应该放在这里，作为结构化数据的补充，而不是作为入口的门槛。

> 设计要点：AI 不是省掉产品设计的借口。用户不擅长凭空描述身体状态，AI 也不擅长从一句「有点痛」里问出全部信息。让结构化流程拿到 80% 的信息，AI 负责剩下 20% 的追问和解释——这才是 AI 用对地方。

---

### Tab 3 · 结果页 —— 走完自查立刻给回报（最关键的一屏）

**绝对不能说「再记几条才能看到规律」。** 第一次就必须给完整的四件事：

1. **一个判断（带可能性分级）**
   「最可能是肩袖肌腱受到激惹，而不是撕裂 —— 依据：你能主动把手举过头，且没有夜间剧痛。」
   → 关键在于**说出依据**。说了依据，用户才知道后面为什么要一次次复测。

2. **一个恢复分数** + 四个贡献因子（可点开看各自数值与解释）

3. **今天就能做的三件事**：1 个动作、1 个要避开的动作、1 个要观察的信号

4. **一条预期时间线**
   「这类问题通常 1–3 周缓解。7 天后我会提醒你复测；如果没有改善，说明假设需要修正。」
   → 这一句同时完成了三件事：给预期、给回访理由、埋下「复测」这个留存钩子。

---

### Tab 4 · Myself —— 从抽象计数改成「我的部位档案」

删掉 "Thoughts 2 / 1 signal taking shape"。改成每个受伤部位一张卡，点进去是这个部位的完整档案：

- **恢复曲线**：分数随时间变化（Oura 的 Trends）
- **当前阶段**：急性期 → 恢复期 → 重返运动，每个阶段写明「这个阶段的目标是什么」
- **分项趋势**：疼痛、活动度、功能影响各自的曲线
- **复测提醒**：到期提示重做动作测试
- **事件时间线**：什么时候受伤、什么时候开始好转、期间做了什么

---

### Tab 5 · Insights —— 分成两层，让它永远不空

- **上半｜个人洞察**（需要数据）
  「你的肩痛在深蹲日的第二天加重 —— 已经出现 3 次。」
  「你的活动度在这周提升了 20°，但疼痛评分没变 —— 这通常是好现象。」
- **下半｜知识库**（永远可读，不依赖数据）
  分类：认识疼痛 / 常见部位 / 恢复原理 / 训练与负荷 / 什么时候必须看医生

这样这一页在第 0 天就有内容，而不是一朵云配一句 "A pattern shows after a few entries"。

---

### Tab 6 · Calendar —— 从记录日历改成恢复日历

不是「我哪天记了什么」，而是「我该做什么」：今日康复动作打卡、复测日、阶段里程碑。让日历成为计划工具而不是档案柜。

## 四、恢复分数（Recovery Score）的可实现口径

0–100 分，四个贡献因子，每个都可点开看自己的数值和解释（照搬 Oura contributors 的做法）：

| 因子 | 数据来源 | 建议权重 |
|---|---|---|
| 疼痛强度 | 当前疼痛评分 0–10 | 35% |
| 活动度 / 功能 | 标准动作能否完成、完成到什么程度 | 30% |
| 日常影响 | 穿衣 / 提物 / 睡眠受影响程度（3–4 个点选题） | 20% |
| 变化趋势 | 最近 3 次评估的斜率 | 15% |

两个纪律：
- **可解释优先于精确**。用户信任分数，是因为能点开看见「为什么是 62 分」，不是因为公式复杂。
- **文案上说清楚这是「你的主观状态被量化了」，不是医学诊断指标。**

## 五、Onboarding：30 秒内摸到第一个价值

不要一上来就要注册。三屏：

1. **价值主张**（三句话）：Nomon 帮你搞清楚 —— 这个疼是什么 / 能不能继续练 / 大概多久能好
2. **身体地图**：「现在哪里不舒服？」（提供「暂时没有，先看看」→ 直接进知识库）
3. **2 分钟自查 → 出结果**，**这时候才**请求注册："注册一下，把你的恢复记录保存下来。"

先证明有用，再要账号。这个顺序不能反。

## 六、知识卡内容清单（对标 Oura 的「睡眠分数 / 生物钟 / 睡眠负债」）

每张 200–400 字 + 一张图，30 秒读完。首批 12 张：

1. 疼痛 ≠ 损伤：疼痛评分怎么用
2. 延迟性肌肉酸痛（DOMS）和真正的伤怎么区分
3. 急性期 48 小时该做什么：PEACE & LOVE（RICE 已经过时了）
4. 冰敷到底该不该用
5. 什么叫「可接受的疼痛」：0–3 分原则
6. 活动度（ROM）是什么，为什么它比疼痛更能反映恢复进度
7. 负荷管理：为什么「完全休息」经常反而拖慢恢复
8. 离心训练为什么对肌腱特别有效
9. 肌肉 / 肌腱 / 韧带：愈合时间为什么差这么多
10. 六种红旗信号：出现就别自己处理，去医院
11. 什么时候可以重返运动：返赛标准怎么定
12. 为什么恢复不是直线：平台期和小反复是正常的

> 这些卡是双重资产：既是冷启动的内容，又是诊断结果的解释弹药——结果页可以直接引用（「因为你符合 X，建议读这张」）。

## 七、安全底线（健康类产品的硬约束，必须先于功能）

- **红旗筛查强制前置**，命中直接转向就医建议，不给自我处理方案
- 全程措辞用「可能 / 常见于 / 建议」，**永远不用「诊断 / 确诊」**
- 每个结果页固定一行免责说明 + 一个「找专业人士」入口
- 不给任何药物剂量建议
- 未成年人受伤、外伤性事故、疼痛持续加重 → 一律转向线下

这不只是合规，它本身就是产品可信度的一部分。一个会说「这个我不该替你判断，去看医生」的 app，比一个什么都敢答的 app 更值得信任。

## 八、优先级建议

| 优先级 | 内容 | 解决什么 |
|---|---|---|
| **P0** | 身体地图入口 · 2 分钟自查结构化流程 · 即时结果页 · 12 张知识卡 | 直接解决「不知道输什么、不知道有什么用」 |
| **P1** | 恢复分数 + 贡献因子 · 部位档案与恢复曲线 · 复测提醒 | 建立留存和长期价值 |
| **P2** | 视频动作分析 · 恢复日历 / 康复计划 · 诱因标签的趋势关联 | 拉开与通用聊天机器人的差距 |

**关于视频拍摄的建议**：放 P2，而且不要做成「AI 看视频给诊断」（可靠性和责任都撑不住）。做成 **「标准动作对照 + 活动度测量」** 更实际也更容易实现——把摄像头当量角器用，测抬臂角度、屈膝角度，得到客观、可复测、可画曲线的数字。这才是 Nomon 真正的「传感器」，也是它相对纯聊天 AI 的护城河。

---

## 九、一句话总结

> **现在的 Nomon 是「你先说，我再帮你」；应该改成「我先让你看见自己的身体，你自然就想说了」。**

Oura 的成功不在于指环有多准，而在于它把「一个用户不了解的领域」变成了「几个用户看得懂、点得开、每天想看一眼的数字」。Nomon 要做的是同一件事：把「我这里有点痛」这个模糊的感觉，变成一个可测量、可追踪、有解释的数字。
