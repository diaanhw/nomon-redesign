Nomon 恢复设计

Nomon 测试版 · 体验诊断与重构建议

让用户先看见自己的身体，
他自然就愿意开口

Nomon 现在的第一屏是一个空白的输入框。这份方案参照 Oura 的产品结构，把它改成「先给予、后索取」——用户不用打字就能拿到第一个有用的结论，然后才愿意持续记录。

2026-08-18 依据：测试版 Today / Myself / Insights 四页面实测 参照：Oura App

Oura 的成功不在于指环测得多准，而在于它把一个用户完全不懂的领域，变成了几个看得懂、点得开、每天想看一眼的数字。Nomon 要做的是同一件事：把「我这里有点痛」这个模糊的感觉，变成一个可测量、可追踪、有解释的数字。

方案的全部出发点

一 · 四个诊断

都不是文案问题，是顺序问题。

顺序

给予和索取的顺序反了

Oura 是先给后要：戴上指环睡一觉，第二天早上就有三个分数和一整套解释，用户是被「我想搞懂这个数字」推着去读知识、打标签。

Nomon 是先要后给：进门就是一个空文本框「写下来」，Insights 页还明说 “A pattern shows after a few entries”——把回报推到了一个未知的将来。用户不是不愿意输入，是不愿意为一个还没证明自己有用的东西输入。

输入

把最难的输入方式设成了默认

「肩膀举高时有点痛」这种自由文本，对用户是一道开放式作文题：不知道该写多细、不知道写了会怎么用、怕写错。

Oura 的主输入是零成本的传感器，辅助输入是轻量点选。Nomon 没有传感器，但完全可以用结构化自评替代作文：点部位 → 选场景 → 做两三个标准动作 → 拖滑条打分。信息量远大于一句话，认知成本却低得多。

内容

完全缺失「知识」这一层

Oura 里的睡眠分数、生物钟、睡眠负债这些知识卡，真正的作用是在用户还没有任何数据时，告诉他这个 app 懂什么、能帮你什么。它是不依赖用户数据就能消费的内容资产。

Nomon 目前没有这一层，所以首屏只能是空的，用户也就无从判断值不值得投入。

视角

Myself 页展示的是系统内部状态

“Thoughts 2 / 1 signal taking shape” 是开发者视角。用户真正关心的只有三件事：我的肩膀现在怎么样？什么时候能好？今天能不能去练？

二 · 把 Oura 的四层结构原样搬过来

Nomon 缺的不是功能，是这四层的对应物。

Oura 的层Nomon 的对应物
指环传感器（被动采集）→动作自查：2 分钟、3 个标准动作、点选加滑条
Readiness / Sleep / Activity 分数→恢复分数：按受伤部位，0–100
Contributors（HRV、静息心率、体温…）→贡献因子：疼痛强度 / 活动度 / 日常功能 / 变化趋势
Learn 知识库→知识卡库：12–20 张，冷启动内容兼解释弹药
Tags 标签→诱因标签：久坐 / 深蹲日 / 跑量突增 / 睡姿
Trends 趋势→恢复曲线 + 阶段：急性期 / 恢复期 / 重返运动

三 · Today 首屏怎么改

核心：把空文本框换成身体地图。点一个部位的成本几乎为零，而它给出的信息比用户随手写的一句话更结构化。

Today我的部位Insights计划

三段结构

  • 顶部｜身体地图。人形剪影，正背面可切换，可点选部位。有记录的部位显示状态色（红=急性 / 黄=恢复中 / 绿=已缓解）。没有任何数据时也是完整可交互的：「哪里不舒服？点一下。」
  • 中部｜今日卡片。有数据时是分数 + 一句自然语言解释 + 今天的三条建议；没数据时是一张显眼的行动卡「2 分钟自查，看看这是什么问题」。
  • 下部｜知识卡流。永远有内容。新用户第一次打开，看到的就是这些卡填满屏幕，滑两下就明白这个 app 懂运动损伤。

四 · 「2 分钟自查」替代自由文本

五步，一步一屏，全部是点选和滑条，不需要打字。

01

哪里

身体地图点选：肩 / 膝 / 腰 / 踝…，再细分前后侧。

02

什么时候开始的

今天 / 这周 / 一个月内 / 更久。这一步决定「急性还是慢性」，是后面所有建议的分岔点。

03

怎么弄的

举重物 / 跑步 / 球类扭伤 / 睡醒就痛 / 说不清。「说不清」必须是合法选项。

04

动作测试

针对该部位给 2–3 个标准动作，每个配示意图或三秒短视频：「手臂从体侧举过头顶」→ 滑条打疼痛 0–10，再三档选「能举到哪」。这是 Nomon 版的传感器读数，可量化、可复测、可画曲线。

05

红旗筛查

麻木 / 明显无力 / 关节外观变形 / 夜间痛醒 / 发烧。命中任意一条，流程立即转向「建议尽快就医」，不再给自我处理方案。

走完五步之后，才出现自由文本：「还有什么想补充的？（可跳过）」 —— AI 对话应该放在这里，作为结构化数据的补充，而不是作为入口的门槛。

顺带一句：AI 不是省掉产品设计的借口。用户不擅长凭空描述身体状态，AI 也不擅长从一句「有点痛」里问出全部信息。让结构化流程拿到八成信息，AI 负责剩下两成的追问和解释——这才是 AI 用对了地方。

五 · 结果页：第一次就必须给满

最关键的一屏。绝对不能说「再记几条才能看到规律」。

A

一个带可能性分级的判断，并说出依据

「最可能是肩袖肌腱受到激惹，而不是撕裂——依据：你能主动把手举过头，且没有夜间剧痛。」说了依据，用户才理解后面为什么要一次次复测。

B

一个恢复分数

附四个贡献因子，每个都能点开看自己的数值和解释。

C

今天就能做的三件事

一个动作、一个要避开的动作、一个要观察的信号。不要给十条。

D

一条预期时间线

「这类问题通常 1–3 周缓解。7 天后我会提醒你复测；如果没有改善，说明假设需要修正。」这一句同时给了预期、给了回访理由、埋下了「复测」这个留存钩子。

六 · 恢复分数怎么算

0–100 分，四个贡献因子，每个都可点开看数值和解释——照搬 Oura contributors 的做法。

疼痛强度35%
活动度 / 功能30%
日常影响20%
变化趋势15%

数据来源依次是：当前疼痛评分 0–10 ／ 标准动作能否完成、完成到什么程度 ／ 穿衣、提物、睡眠受影响程度的三四个点选题 ／ 最近三次评估的斜率。

两条纪律：可解释优先于精确——用户信任分数是因为能点开看见「为什么是 62 分」，不是因为公式复杂；文案上说清楚这是「你的主观状态被量化了」，不是医学诊断指标。

七 · 其余几个页面

Myself → 我的部位档案

删掉「Thoughts 2 / 1 signal taking shape」。改成每个受伤部位一张卡，点进去是这个部位的完整档案：恢复曲线、当前阶段（急性期 → 恢复期 → 重返运动，每个阶段写明这一阶段的目标是什么）、疼痛与活动度的分项趋势、复测提醒、事件时间线。

Insights → 分成两层，永远不空

上半是个人洞察（需要数据）：「你的肩痛在深蹲日的第二天加重，已经出现 3 次」「活动度这周提升了 20°，但疼痛评分没变——这通常是好现象」。下半是知识库（永远可读），分五类：认识疼痛 / 常见部位 / 恢复原理 / 训练与负荷 / 什么时候必须看医生。

Calendar → 恢复日历

不是「我哪天记了什么」，而是「我该做什么」：今日康复动作打卡、复测日、阶段里程碑。让日历成为计划工具，不是档案柜。

Onboarding：30 秒摸到第一个价值

不要一上来就要注册。三屏：一，三句话价值主张——Nomon 帮你搞清楚这个疼是什么、能不能继续练、大概多久能好；二，身体地图「现在哪里不舒服？」（提供「暂时没有，先看看」直接进知识库）；三，2 分钟自查出结果。这时候才请求注册：「注册一下，把你的恢复记录保存下来。」先证明有用，再要账号，这个顺序不能反。

八 · 首批 12 张知识卡

每张 200–400 字加一张图，30 秒读完。它们既是冷启动的内容，又是结果页的解释弹药——可以直接被引用：「因为你符合 X，建议读这张」。

01疼痛 ≠ 损伤：疼痛评分怎么用
02延迟性肌肉酸痛和真正的伤怎么区分
03急性期 48 小时：PEACE & LOVE（RICE 已过时）
04冰敷到底该不该用
05什么叫「可接受的疼痛」：0–3 分原则
06活动度为什么比疼痛更能反映恢复
07为什么「完全休息」经常拖慢恢复
08离心训练为什么对肌腱特别有效
09肌肉 / 肌腱 / 韧带的愈合时间差异
10六种红旗信号：出现就别自己处理
11什么时候可以重返运动

九 · 安全底线

健康类产品的硬约束，必须先于功能实现。

不可协商的五条

  • 红旗筛查强制前置，命中直接转向就医建议，不给自我处理方案
  • 全程措辞用「可能 / 常见于 / 建议」，永远不用「诊断」「确诊」
  • 每个结果页固定一行免责说明，加一个「找专业人士」的入口
  • 不给任何药物剂量建议
  • 未成年人受伤、外伤性事故、疼痛持续加重——一律转向线下

这不只是合规。一个会说「这个我不该替你判断，去看医生」的 app，比一个什么都敢答的 app 更值得信任——它本身就是产品可信度的一部分。

十 · 优先级

P0

身体地图入口 · 2 分钟自查 · 即时结果页 · 12 张知识卡

直接解决「不知道该输入什么、不知道有什么用」。这一层做完，产品才算成立。

P1

恢复分数与贡献因子 · 部位档案与恢复曲线 · 复测提醒

建立留存和长期价值：让用户有理由第二次、第十次打开。

P2

视频动作分析 · 恢复计划日历 · 诱因标签的趋势关联

拉开与通用聊天机器人的差距。

关于视频拍摄

建议放 P2，而且不要做成「AI 看视频给诊断」——可靠性和责任都撑不住。做成 「标准动作对照 + 活动度测量」 更实际也更容易实现：把摄像头当量角器用，测抬臂角度、屈膝角度，得到客观、可复测、可画曲线的数字。这才是 Nomon 真正的传感器，也是它相对纯聊天 AI 的护城河。

现在的 Nomon 是「你先说，我再帮你」。
应该改成「我先让你看见自己的身体，你自然就想说了」。
